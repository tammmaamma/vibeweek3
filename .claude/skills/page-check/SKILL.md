# page-check

HTML 파일을 5가지 관점에서 점검하고, 문제를 🔴 심각 / 🟡 주의 / 🟢 제안 세 등급으로 분류해 보고한다.

## 점검 항목과 등급 기준

| # | 항목 | 🔴 심각 | 🟡 주의 | 🟢 제안 |
|---|------|---------|---------|---------|
| 1 | `<title>` | — | 태그 자체가 없음 | 태그는 있으나 내용이 비어 있음 |
| 2 | 내부 링크 | `href="#id"` 또는 상대 경로가 실제 대상(요소·파일)을 찾지 못함 | — | `/`로 시작하는 루트 상대경로처럼 자동 검증이 불가능해 수동 확인이 필요한 경우 |
| 3 | 이미지 alt | — | `<img>`에 `alt` 속성 자체가 없음 | — |
| 4 | 모바일 viewport | `<meta name="viewport">` 자체가 없음 | — | 있지만 `width=device-width` 권장값이 없음 |
| 5 | UTF-8 인코딩 | 비ASCII(한글 등) 문자가 있는데 charset 선언이 없거나 UTF-8이 아님 | — | 비ASCII 문자는 없지만 charset 선언 자체가 없음(향후 대비 권장) |

깨진 내부 링크·viewport 부재·잘못된 인코딩은 페이지 사용성을 실제로 깨뜨리므로 심각으로 분류하고, title·alt 누락은 접근성·SEO 문제이지만 페이지 자체는 작동하므로 주의로 분류한다.

## 실행 절차

1. 점검 대상 결정: 사용자가 파일을 지정하면 해당 파일만, 지정하지 않으면 프로젝트 전체의 `*.html`(`.git`, `node_modules` 제외)을 대상으로 한다.
2. `scripts/check_page.py`를 실행해 자동 점검한다. 표준 라이브러리(`html.parser`)만 사용하므로 별도 설치가 필요 없다.
   ```
   python .claude/skills/page-check/scripts/check_page.py [파일...]
   ```
   인자 없이 실행하면 현재 디렉터리 하위 모든 `.html` 파일을 재귀적으로 점검한다.
3. 스크립트 출력(파일별 🔴/🟡/🟢 목록과 마지막 요약 건수)을 근거로 삼되, 다음은 스크립트가 판단할 수 없으므로 필요하면 직접 파일을 열어 확인한다:
   - 외부(`http://`, `https://` 등) 링크의 실제 접속 가능 여부 — 스크립트는 내부·상대 경로만 검사한다.
   - 루트 상대경로(`/`로 시작) 링크의 실제 대상.
   - alt 텍스트의 "품질" — 속성 존재 여부만 확인하며, 내용이 이미지를 잘 설명하는지는 판단하지 않는다.
4. 결과를 한국어로 정리해 사용자에게 보고한다. 등급별로 묶어서 제시하고, 어떤 등급에도 해당하는 문제가 없으면 "🟢 문제 없음"으로 명시한다.
5. 사용자가 수정을 요청하면 발견된 문제를 실제 파일에서 고친 뒤, 스크립트를 다시 실행해 해결됐는지 재검증한다.

## 스크립트

- `scripts/check_page.py` — 무의존성 점검 스크립트. HTML을 파싱해 `<title>`, `<meta name="viewport">`, `<meta charset>`/`http-equiv="Content-Type"`, `<img>`의 `alt`, `<a href>`를 추출하고 위 등급 기준에 따라 분류해 콘솔에 출력한다.

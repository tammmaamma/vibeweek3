# security-check

HTML/JS 파일을 4가지 보안 관점에서 점검하고, 문제를 🔴 심각 / 🟡 주의 / 🟢 제안 세 등급으로 분류해 보고한다.

## 점검 항목과 등급 기준

| # | 항목 | 🔴 심각 | 🟡 주의 | 🟢 제안 |
|---|------|---------|---------|---------|
| 1 | 하드코딩된 비밀번호·API 키 | `password=`/`apiKey=`/`AKIA...`/개인키 블록처럼 실제 값으로 보이는 시크릿이 코드에 박혀 있음 | — | — |
| 2 | innerHTML XSS | 변수·템플릿 리터럴이 이스케이프 없이 그대로 `innerHTML`에 들어감 | 이스케이프/새니타이즈 함수를 호출하는 것처럼 보이지만 실제 동작은 확인이 필요함 | — |
| 3 | console.log 민감정보 노출 | `console.*` 호출 인자에 password/token/secret/apiKey 등 민감 키워드가 포함됨 | — | — |
| 4 | http:// 외부 요청 | `localhost`/`127.0.0.1`이 아닌 실제 외부 호스트로 `http://` 요청·리소스 로드 | `http://localhost`, `http://127.0.0.1` 등 로컬 개발용으로 보이는 http:// 사용 | — |

시크릿 노출과 실제 외부 도메인向 평문 http:// 통신은 그 자체로 데이터 유출·탈취로 이어질 수 있어 심각으로 분류한다. innerHTML은 값이 이스케이프 함수로 감싸여 있으면 의도적으로 안전 처리했을 가능성이 있어 주의로 낮추고, 로컬 호스트 http:// 는 배포 전 확인이 필요한 수준으로 낮춘다.

## 실행 절차

1. 점검 대상 결정: 사용자가 파일을 지정하면 해당 파일만, 지정하지 않으면 프로젝트 전체의 `*.html`, `*.js`(`.git`, `node_modules` 제외)를 대상으로 한다.
2. `scripts/check_security.py`를 실행해 자동 점검한다. 표준 라이브러리(`re`)만 사용하므로 별도 설치가 필요 없다.
   ```
   python .claude/skills/security-check/scripts/check_security.py [파일...]
   ```
   인자 없이 실행하면 현재 디렉터리 하위 모든 `.html`/`.js` 파일을 재귀적으로 점검한다.
3. 스크립트는 정규식 기반 줄 단위 스캔이라 다음은 판단할 수 없으므로, 결과가 애매하거나 스크립트가 놓쳤을 수 있는 부분은 직접 파일을 열어 확인한다:
   - 여러 줄에 걸쳐 작성된 문(statement) — 예: `innerHTML =` 대입식이 다음 줄로 이어지는 경우.
   - 시크릿처럼 보이는 값이 실제로는 플레이스홀더(`YOUR_API_KEY`, `<...>`, `${...}`, `process.env.X`)인지 여부 — 스크립트가 흔한 플레이스홀더 패턴은 걸러내지만 완벽하지 않다.
   - 이스케이프/새니타이즈 함수(`escapeHtml`, `DOMPurify.sanitize` 등)가 실제로 안전하게 구현되어 있는지 — 스크립트는 호출 여부만 확인하고 구현 내용은 검증하지 않는다.
4. 결과를 한국어로 정리해 사용자에게 보고한다. 등급별로 묶어서 제시하고, 각 항목마다 스크립트가 출력한 `파일:라인` 근거를 그대로 인용한다. 어떤 등급에도 해당하는 문제가 없으면 "🟢 문제 없음"으로 명시한다.
5. 이 스킬은 점검·보고 전용이다 — 사용자가 명시적으로 수정을 요청하지 않는 한 코드를 고치지 않는다. 수정을 요청하면 발견된 문제를 실제 파일에서 고친 뒤, 스크립트를 다시 실행해 해결됐는지 재검증한다.

## 스크립트

- `scripts/check_security.py` — 무의존성 점검 스크립트. HTML/JS 텍스트를 정규식으로 스캔해 하드코딩된 시크릿, `innerHTML` 대입식, `console.*` 호출, `http://` 리터럴을 추출하고 위 등급 기준에 따라 분류해 콘솔에 출력한다.
